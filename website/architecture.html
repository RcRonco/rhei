Architecture

How Rhei works

Shared-nothing, disaggregated-state streaming engine. Compute scales independently from storage. All data flows as Arrow RecordBatch buffers — no row-by-row execution path.

Execution Model

Arrow columnar, not row-by-row

All data flows as Apache Arrow RecordBatch buffers. No deserialization on the hot path. Vectorized compute through the entire pipeline.

Concept Type Description
Schema RheiSchema trait Defines Arrow schema, builder, zero-copy view, and column accessors
Typed buffer RheiBuffer<T> RecordBatch + selection vector (boolean mask for zero-copy filtering)
Transport ErasedBuffer Type-erased RecordBatch + mask + schema_id for Timely dataflow transport
Operator StreamFunction Async trait: process(RheiBuffer<I>, ctx) → BufferOutput<O>
Exchange key_by + seahash Two-stage: split rows by hash % workers → route via Timely Exchange pact
Serialization Arrow IPC Cross-worker data transfer. Self-describing, columnar-native format. 
Processing Granularities:

  Row-level     Iterate RheiBuffer<T> via zero-copy View<'a> references.
               For custom stateful logic per-element.

  Batch-level   Receive full RheiBuffer<T>. For windows, aggregations.
               Amortize overhead across thousands of rows.

  Column-level  Arrow compute kernels on column arrays.
               Selection vectors enable zero-copy filter expressions.
State Management

Three-tier state hierarchy

Hot state in RAM for active keys, warm cache on local NVMe, cold storage on S3. Each tier optimized for its access pattern. Workers are stateless — they read through the hierarchy.

Tier Backend Latency Capacity Behavior
L1 HashMap<Bytes, Bytes> ~1μs RAM-bounded Buffers writes. Dirty keys flushed to L3 on checkpoint. Compaction + eviction policies.
L2 Foyer HybridCache ~1ms NVMe-bounded Local read-through cache. Handles L1 misses without network. Admission control.
L3 SlateDB on S3 ~50ms Unlimited Source of truth. SSTable uploads. Enables stateless autoscaling. 
State Access Patterns:

  Hot path (zero I/O)
    Batch arrives → operator processes → state read/write in L1 → output emitted
    No blocking. No network. Microsecond latency.

  Cold path (async fetch)
    L1 miss → block_in_place → async fetch from L2/L3 → load into L1 → continue
    Transparent to operator code. Same StateContext API.

  Checkpoint path
    Frontier advances → L1 dirty keys flush to SlateDB → SSTable upload to S3
    → manifest written → source offsets committed → next epoch begins

Key Isolation:

    State keys are prefixed: {operator_name}/{user_key}
    Multi-process:          p{pid}/w{idx}/{operator}/{key}
    No cross-operator interference. No cross-worker conflicts.
Checkpointing

Consistent snapshots with offset tracking

Checkpoint coordination triggered by Timely frontier advancement. Source offsets committed after state is durable.

Checkpoint Protocol:

  1. Timely frontier advances (all workers finish epoch N)
  2. Each worker flushes L1 dirty keys → SlateDB → S3
  3. Workers report readiness via checkpoint channel
  4. Coordinator writes merged checkpoint manifest
  5. Source offsets committed (Kafka consumer group)
  6. Epoch N+1 begins

Manifest contents:

  ├── operator states (prefixed key ranges per worker)
  ├── source offsets (topic/partition → offset)
  ├── topology metadata (process count, workers per process)
  └── epoch number

Recovery:

  $ cargo run -- --from-checkpoint s3://bucket/manifests/epoch-42.json
  → Load manifest → seek Kafka to checkpointed offsets → resume processing
Runtime

Async/sync bridge architecture

Sources and sinks are async Tokio tasks. Timely Dataflow is synchronous and runs on blocking threads. Bounded channels bridge the two worlds.

┌───────────────────────┐           ┌───────────────────────┐
│ Tokio Runtime         │           │ Timely Runtime        │
│                       │           │                       │
│ KafkaSource (async)   │   mpsc    │ Dataflow operators   │
│     │                 │ ────────▶ │     │                 │
│     ▼                 │  bounded  │     ▼                 │
│ produce RheiBuffer    │           │ consume ErasedBuffer  │
│                       │           │     │                 │
│ KafkaSink (async)     │   mpsc    │     ▼                 │
│     ▲                 │ ◀──────── │ emit ErasedBuffer    │
│     │                 │  bounded  │                       │
│ consume RheiBuffer    │           │ spawn_blocking       │
│                       │           │                       │
└───────────────────────┘           └───────────────────────┘

Process Layers:

  PipelineController  →  config, lifecycle, CLI parsing
       │
       ▼
  TaskManager         →  background services, source/sink bridging
       │
       ▼
  DataflowExecutor    →  per-worker Timely DAG compilation and execution
Clustering

From single thread to distributed

Three deployment modes with the same pipeline code. Scale compute independently — state lives in S3.

Mode Config Communication State
Multi-thread .with_workers(N) In-process channels Per-worker L1, shared L2/L3
Multi-process .from_env() TCP (Timely networking) Per-process SlateDB, shared S3 bucket

Error Handling

Graceful failure, not silent drops

ErrorPolicy::Skip Log warning, drop the failed element, continue processing. Default for non-critical paths.
ErrorPolicy::SendToDlq Route failed elements to a DlqSink. Errors are propagated, never silently swallowed.
DlqSink trait Pluggable backends: FileDlqSink, LogDlqSink, KafkaDlqSink. Implement your own.
on_error() hook Per-operator error recovery callback on StreamFunction. Custom retry or fallback logic.
Graceful shutdown Drain in-flight batches → flush state → write checkpoint → commit offsets → exit.
