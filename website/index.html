Rhei: stateful stream processing
for Rust, built on Arrow

Rhei is a distributed streaming engine with columnar execution, tiered disaggregated state, and first-class operational tooling. Same pipeline code runs single-threaded on your laptop or multi-process on a cluster.

The API

Define pipelines, not plumbing

Rhei's builder API is fluent and type-safe. Source to sink validated at compile time. Windowing, joins, and stateful operators compose naturally.

pipeline.rs 
use rhei::prelude::*;

#[rhei::pipeline]
fn main(graph: &DataflowGraph) {
    let orders = graph.source(KafkaSource::new(broker, group, &["orders"])?);

    orders
        .map(|msg| parse_order(msg))
        .filter_fn(|o| o.amount > 50.0)
        .key_by(|o| o.customer_id.clone())
        .window(TumblingWindow::new(Duration::from_secs(60)))
        .aggregate(OrderAggregator)
        .sink(KafkaSink::new(broker, "aggregated-orders")?);
}
Developer Experience

Built for the streaming developer

Every design decision optimizes for the person writing and operating pipelines. Rhei gives you the tooling to develop, debug, and observe streaming systems without friction.

# Proc macro entrypoint

#[rhei::pipeline] generates a full CLI with --workers, --from-checkpoint, --metrics-addr, and cluster flags. Zero boilerplate.

$ TUI dashboard

rhei run --tui gives you a live terminal dashboard: pipeline graph, per-worker throughput, backpressure metrics, and structured logs.

↻ Checkpoint fork

--from-checkpoint <s3-url> reproduces production state locally. Copy-on-write backend means safe debugging against real data without touching prod.

→ Attach to running pipelines

rhei run --attach <url> connects to a live pipeline and streams health, metrics, and structured logs to your terminal in real time.

⚡ Zero-config observability

Prometheus at /metrics, health probes at /healthz and /readyz, JSON metrics API. Structured tracing spans per-operator, per-worker.

✗ Dead letter queue

Pluggable DlqSink trait routes failed records to file, Kafka, or custom backends. Per-operator error policies — skip or send to DLQ.

Get started

terminal 
# New pipeline project
$ cargo new my-pipeline && cd my-pipeline
$ cargo add rhei tokio --features tokio/full

# Run with live TUI dashboard
$ cargo run -- --workers 4 --tui

# Fork production state locally for debugging
$ cargo run -- --from-checkpoint s3://bucket/checkpoint --offset-delta 1000

# Attach to a running pipeline's metrics stream
$ rhei run --attach http://pipeline-host:9090
Operators

Built-in operators for common streaming patterns

Compose them with the builder API or implement StreamFunction directly for full control over batch processing and state.

TumblingWindow Fixed-size time windows with pluggable aggregators and watermark-based triggers
SlidingWindow Overlapping time windows for moving averages and rolling computations
SessionWindow Gap-based windows per key — group activity bursts with configurable inactivity timeout
TemporalJoin Key-based join with configurable timeout and automatic state eviction for unmatched events
SequenceDetect Ordered event pattern matching — MATCH_RECOGNIZE semantics without SQL. NFA-backed.
KeyedState<K, V> Typed state wrapper with automatic serde (JSON or bincode). Access via OperatorContext in any custom operator.
map / filter / flat_map Stateless combinators operating on Arrow batches with selection vectors (no data copying)
key_by / merge Hash-based exchange across workers (seahash % num_workers) and fan-in from multiple streams
Architecture

Disaggregated state, columnar execution

Rhei separates compute from storage. Workers are stateless — they read through a tiered state hierarchy. Scale compute up or down without migrating state.

Tier Backend Latency Role
L1 — Hot HashMap memtable ~1μs Buffer writes and serve hot reads. Dirty keys flushed on checkpoint.
L2 — Warm Foyer HybridCache ~1ms Local NVMe cache. Serves L1 read misses without network round-trips.
L3 — Cold SlateDB on S3 ~50ms Source of truth with infinite capacity. Enables stateless autoscaling.

Full details on the execution model, checkpoint protocol, and async bridge — read the architecture guide.

Clustering

Same pipeline code, any deployment target

.with_workers(N) Multi-thread — N worker threads, shared-nothing state per worker, single process
.from_env() Multi-process — N processes over TCP, coordinated checkpoints via S3, independent state backends
